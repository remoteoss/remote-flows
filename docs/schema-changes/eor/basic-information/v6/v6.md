# Basic Information v6

## Overview

Schema v6 limits how far back `seniority_date` can go. It is available for all countries that ask for that field.

## Key Changes

- When `has_seniority_date` is "yes", `seniority_date` can be at most 5 years before `provisional_start_date`. The same day 5 years earlier is allowed.
- The `seniority_date` date picker's `minDate` follows `provisional_start_date` minus 5 years. A 29 February start gives 28 February. Before a start date is entered, it stays 5 years before today.

## Caveats

- The rule applies to new and updated basic information submitted against this version, and only for employers that onboarding reserve payments apply to.
- Stored employments are not re-checked.
- Send a `seniority_date` on or after `provisional_start_date` minus 5 years, or send `has_seniority_date` "no".
- Pin to version 5 to keep the previous shape.

## Migration

```tsx
// Before
<OnboardingFlow {...onboardingProps} />;

// After
<OnboardingFlow
  options={{
    jsonSchemaVersion: {
      employment_basic_information: 6,
    },
  }}
/>;
```
