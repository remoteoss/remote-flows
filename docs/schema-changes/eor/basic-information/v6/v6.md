# Basic Information v6

## Overview

Schema v6 adds a limit on how far back `seniority_date` can be. It is available for all countries.

It includes the v5 change to `tax_servicing_countries`, see [v5](../v5/v5.md).

## Key Changes

- When `has_seniority_date` is `yes`, `seniority_date` can be at most 5 years before `provisional_start_date`. The same day 5 years earlier is allowed.
- The date picker's minimum date follows `provisional_start_date` minus 5 years. A 29 February start gives 28 February. Before a start date is entered, it stays 5 years before today.

## Caveats

- The rule applies to new and updated basic information submitted against this version, only for employers that onboarding reserve payments apply to. Stored employments are not re-checked.
- Send a `seniority_date` on or after `provisional_start_date` minus 5 years, or send `has_seniority_date` as `no`. Pin to v5 to keep the previous shape.

## Migration

```tsx
// Before
<OnboardingFlow {...onboardingProps} />;

// After
<OnboardingFlow
  options={{
    jsonSchemaVersion: {
      employment_basic_information: 6,
    },
  }}
/>;
```
